## 5. 部署与升级


## 7. 已知限制

| 项 | 影响 | 建议 |
| --- | --- | --- |
| 用例固定模板导入未实现 | 只能逐个录入或 AI 生成 | 按模板做 xlsx 导入（B2 后续） |
| 任务超时与 Worker 重启恢复未做 | 极端故障需人工重置运行 | 增加任务级超时与恢复点检查 |
| 尝试无步骤级关联 | 无法从单步跳到证据 | 记录 `step_key` 与步骤证据索引 |
| 缺陷分类为规则建议 | 复杂失败分类可能不准 | 接入模型并复用 suggestion 契约 |
| 回归批次选择器缺失 | 需接口/复测关联批次 | 页面加批次多选 |
| 报告无结论备注/签字 | 报告仅数据事实 | 增加结论文本与确认人 |
| 导出为同源直连下载 | 跨域部署需令牌 | 增加一次性下载令牌 |
| Web 全量验收未跑 | 已跑通 1 条真实 Web 用例（平台登录页）；验收执行器生成的其余 Web 用例无脚本 | 接入真实示例业务 UI 用例后再跑 `--run-ui` |
| 完整镜像重建受浏览器 CDN 网络限制 | 本地 `compose up --build` 在 Playwright 下载失败 | 在网络可用环境执行 `manage.sh rebuild`；本次用 overlay 镜像完成升级演练 |

**代码与交付物完整**：计划 B0–B7 的所有批次均已实现并归档，配套迁移、测试、CI、发布/回退脚本与验收执行器齐全。

**已验证的证据**：

| 证据 | 结果 |
| --- | --- |
| 后端全量测试 | 446 passed / 6 skipped / 0 failed（跳过项为外部依赖集成测试） |
| 前端构建 | `tsc -b` + `vite build` 通过 |
| 旧库升级（真实 MySQL 8.4） | `91de45b6c284 → f6g7h8i9j0k1` 全部迁移通过，回填与基准版本正确 |
| 升级前备份 | 数据库 + uploads + SHA256，可回退 |

| 报告口径 | 零分母不适用、重试保留首次失败、快照不可变、版本对比 |

**真机发现并修复的缺陷**（均已补回归测试）：

1. MySQL 8 不允许 TEXT 列默认值（迁移在实机失败）；
2. 同步执行不回写批次尝试（报告把已通过项算成未执行）；
3. UI 脚本 `expect()` 收到插桩对象（默认模板必然失败）。

**未完成项及原因**（均非代码缺失）：

- 200 次执行窗口（40 自动项 × 5 轮）与 30 条标注需求生成质量：需要示例业务、固定正常构建、可重置数据与模型凭据；
- 其余 Web 验收用例：需要示例业务的真实 UI 脚本；
- 完整镜像重建：本机 Playwright CDN 不可达，演练使用无网络 overlay 镜像；
- 浏览器交互人工确认：版本/评审抽屉、缺陷证据、搜索深链接、报告对比。

**发布建议**：

1. 将当前工作区作为一次发布提交（`app/` 仓库），打 tag；
2. 在可访问 Playwright CDN 的环境执行 `scripts/verify-release.sh` 与 `manage.sh rebuild`；
3. 用 `backend/tools/acceptance_first_release.py --run-api --run-ui` 在预发跑量化验收并归档 JSON；
4. 按 [B7 发布说明](./B7-兼容验证与发布.md) 的检查清单完成预发升级与备份恢复演练后放行。
