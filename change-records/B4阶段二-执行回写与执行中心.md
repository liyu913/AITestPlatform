## 2. 行为

### 2.1 运行 → 尝试同步

`sync_attempt_from_run(db, run_type, run_id)`：

1. 读取运行记录；没有 `cycle_item_id` 则什么都不做（独立运行不受影响）。
2. 按 `(cycle_item_id, original_run_type, original_run_id)` 查找已有尝试：
   - 不存在 → 新建，`attempt_no` 取该批次项最大值 +1；
   - 已存在 → 覆盖状态/摘要/证据；
   - **终态保护**：已是终态（passed/failed/blocked/error/cancelled）时，迟到的 `running` 回调不会把结论改回运行中。
3. 终态时把结果投影到批次项（`result`、`last_run_type/id`、`executed_at`、`actual_result`）与手工用例的 `last_result`。
4. 并发插入撞唯一约束时回滚并改走更新路径，避免重复尝试。

调用点：API/UI Celery 任务结束、agent_once 收尾、功能运行取消。同步失败只记日志，不影响运行为主流程。

### 2.2 统一执行中心

`GET /projects/{pid}/executions?kind=all|manual|api|ui&status=&page=&page_size=`

- 手工：批次计划项（计划名/批次名、资产标题、结果、尝试数、批次链接）。
- 接口 / UI：`ApiRun` / `UiRun`，标题取对应的用例或套件名，`cycle_item_id` 可解析出所属批次。
- 返回 `counts`（各类型总数，始终是全项目口径）与合并后的分页结果；`link` 为项目内相对路径，前端统一拼 `/projects/{id}/`。
- 状态筛选做了跨源别名：`failed` 同时匹配运行的 `error`，`pending` 兼容手工的 `untested`，`running` 只取真正在跑的运行。

前端 [ExecutionCenter.tsx](../frontend/src/routes/ExecutionCenter.tsx) 用 `Segmented` 切换类型、`Select` 过滤状态，分页与筛选写入 URL，刷新和分享后仍能回到同一视图。
