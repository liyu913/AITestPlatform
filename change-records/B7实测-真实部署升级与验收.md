## 2. 升级过程与发现的问题

### 2.1 镜像重建受网络阻塞

`docker compose up --build` 在 Playwright 浏览器下载步骤失败（`ECONNRESET`，cdn.playwright.dev 不可达）。
旧容器未受影响。为完成升级演练，使用一个临时 overlay 镜像（`FROM raina-testhub-backend:local`，
只覆盖 `app/ alembic/ tools/` 并执行 `uv pip install --no-index --no-deps .`，无网络依赖）部署本次代码。
**正式发布仍应在网络可用的环境执行完整镜像构建**；overlay 仅用于本次演练。

### 2.2 MySQL 迁移缺陷（已修复）

首次 `alembic upgrade head` 在 `requirements.acceptance_rules` 失败：

```
(1101, "BLOB, TEXT, GEOMETRY or JSON column 'acceptance_rules' can't have a default value")
```

MySQL 8 不允许 TEXT 列带 `DEFAULT`。SQLite 上不会报错，所以此前的迁移链测试未暴露。修复方式：
TEXT 列先以 nullable 添加 → `UPDATE ... = ''` 回填 → `ALTER ... NOT NULL`；建表语句中的 TEXT 列去掉
`server_default`。涉及 5 个迁移、7 个 TEXT 列（`acceptance_rules`、`data_note`、`attempt.summary`、
缺陷的 `expected_result/actual_result/verification_note`、`defect_status_history.comment`、报告 `summary_text`）。

修复后从备份恢复数据库，重新升级成功：

```
91de45b6c284 -> b2c3d4e5f6g7 -> c3d4e5f6g7h8 -> d4e5f6g7h8i9 -> e5f6g7h8i9j0 -> f6g7h8i9j0k1
```

回填校验（MySQL）：5 条用例全部生成基准版本（`test_case_versions` = 5），`last_result` 为空、生命周期
按旧状态归位，未出现异常数据。

### 2.3 同步执行不回写批次尝试（已修复）

用验收执行器跑真实 API 执行（`sync=true`）时发现：报告显示 5 项「未执行」，但对应接口运行实际已通过。
原因：尝试回写只接在 Celery 任务路径，`POST /api-cases/{id}/run` 的同步分支直接调用执行器后未同步。
修复：为 API/UI 单用例与套件的同步分支补 `sync_attempt_quietly(...)`（失败只记日志），并新增
`tests/test_run_cycle_link.py::test_sync_api_run_writes_batch_attempt` 覆盖。

修复后的验收报告：11 个计划项全部有结果（untested=0），完成比例 100%。

### 2.4 UI 脚本断言包装问题（已修复）

用真实 Web 用例（打开部署栈自身的登录页并断言品牌文案）验证 UI 执行时，运行返回 `error`：

```
Unsupported type: <class 'app.services.ui_automation.ui_runner._InstrumentedLocator'>
```

Playwright 的 `expect()` 会按内部实现类做类型映射，而脚本拿到的是插桩后的 `_InstrumentedLocator`，因此
`expect(page.get_by_text(...))`（正是默认脚本模板的写法）必然失败。修复：注入一个 `script_expect`
包装，调用真实 `expect` 前把插桩的 Locator / Page 解包为原生对象；新增回归测试
`tests/test_ui_automation.py::test_execute_ui_script_expect_accepts_instrumented_locator`。
