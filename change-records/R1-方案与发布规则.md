## 2. 数据与接口

### 迁移 `g7h8i9j0k1l2`（revises `f6g7h8i9j0k1`）

- 新建 `test_schemes`：名称、状态、负责人、当前版本号、范围/策略/风险/方法/准入准出；
- 新建 `test_scheme_versions`：版本号、快照 JSON、变更说明、创建人，`(scheme_id, version_no)` 唯一；
- `test_plans` 增加 `scheme_id`、`scheme_version_id`；
- `test_cases` 增加 `published_version_id`、`published_version_no`、`published_at`；
- 回填：已确认用例把最新已通过版本写入正式发布指针，升级后正式库不为空。

已在 SQLite 迁移链测试与真实 MySQL 8.4 上执行通过。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/projects/{id}/schemes/` | 列表（搜索/状态/分页）、创建（自动生成 v1） |
| GET/PATCH/DELETE | `/projects/{id}/schemes/{sid}` | 详情、编辑（内容变化生成新版本）、删除 |
| GET/POST | `/projects/{id}/schemes/{sid}/versions` | 版本历史、手动留档 |
| GET | `/projects/{id}/test-cases/review-queue` | 待评审队列（版本、提交时间、评审条数） |
| POST | `/projects/{id}/test-cases/{cid}/publish` | 发布指定/当前版本到正式库 |

规则：

- 计划只能引用同项目的方案版本，跨项目返回 404；
- 只有评审通过的版本可以发布；重复发布同一版本返回 409；
- 评审通过时把该版本状态置为 `confirmed`，驳回置回 `draft`，结论与版本绑定。
