## 2. 关键行为

### 2.1 用例生命周期与执行结果

- 写入口唯一：`apply_lifecycle()` 与 `record_execution_result()`；`TestCase.status` 只作生命周期镜像。
- 手工执行（`PATCH /cycles/{cid}/items/{iid}`）与自动执行（`finalize_agent_once`）只写 `last_result`。
- 创建时兼容旧 `status`：`ready/active/done → confirmed`，`passed/failed/blocked → confirmed + last_result`，未知自由文本 → `draft`。
- 更新时发送执行结果词返回 400，提示“执行结果请写入执行记录”。
- 编辑已确认用例、且未显式指定生命周期时，自动回到 `pending_review`（防止旧审批结论继续冒充有效）。

### 2.2 版本与评审

- 创建即写入 v1；每次内容变更写入新版本（含步骤、预期、设计依据、标签）。
- 评审结论写 `test_case_reviews` 并绑定 `version_id`/`version_no`；驳回必须填意见。
- 执行记录在创建时固定 `case_version_no` 与用例快照，后续编辑不改写历史证据。

### 2.3 执行判定（原 `done ⇒ passed` 修复）

判定顺序：

1. 无执行步骤 → `failed`。
2. 任一步骤 `status=error` → `failed`（带上最后错误）。
3. 用例没有可校验预期（每步预期为空/占位符且总体预期为空）→ `blocked`，提示补充预期。
4. 有预期但 trace 中没有任何 `assert_*` 断言 → `blocked`（动作完成 ≠ 业务预期成立）。
5. trace 未以 `done` 结束 → `failed`。
6. 有预期未被断言覆盖 → `blocked`，列出未覆盖项与覆盖率。
7. 全部覆盖且无错误 → `passed`。

判定结果以 `summary_json.judgement` 存入执行记录（覆盖率、未覆盖项、断言数），供页面与报告使用。

### 2.4 归档与历史保护

- 被缺陷/执行项/执行记录引用时 `DELETE` 返回 409 并提示改用归档。
- 归档用例默认不出现在列表，可用 `lifecycle_status=archived`（或 `include_archived=true`）查看。
- 归档用例只读（编辑/送审返回 409），可 `restore` 回草稿。
