### 1.2 行为

- **规则版本 + 模型可追溯**：每条草稿的 `design_trace` 保存 `skill_version`（技能内容摘要）、`source_digest`（引用来源摘要）、`llm_model`、`requirement_id`、`knowledge_library_id`。
- **测试点确认**：分步模式先产出需求分析与测试点，`await_test_points_confirm` 事件返回测试点与 artifacts；客户端确认后带 `agent_resume_from="cases"` 续跑生成用例（原有能力，本次补上规则注入与校验）。
- **统一质量校验**：快速/分步、首次生成/多维评审修订都走 `complete_cases`：
  - 必须每条用例含 `design_trace`、总体期望、至少一步；
  - 每步必须有可观察 `expected`；
  - 引用编号必须来自本次来源，摘录必须逐字命中来源文本（图片除外）；
  - `needs_rule` 用例标题必须含 `[待确认]`；
  - 修订时保留原 `draft_id`，新增用例省略编号。
- **确认可重试且去重**：`POST /ai/confirm-testcases` 按 `(project_id, ai_draft_id)` 去重；内容一致返回原用例 ID，内容变化返回 409，不会产生重复用例；确认后写入 v1 版本快照。
- **草稿可编辑与恢复**：会话 `POST/PUT /ai/sessions` 保存消息、草稿与 artifacts，可原样恢复后再次确认（已有能力，测试覆盖）。

### 2.2 数据结构

`test_cycles`（批次 = 一次有目标构建和环境配置的执行）：

| 字段 | 说明 |
| --- | --- |
| `target_build` | 目标构建 |
| `env_kind` / `env_id` / `env_snapshot_json` | 环境引用 + 创建/切换时的名称与 `base_url` 快照 |
| `credential_ref` | 凭据引用名（密钥本身不进表） |
| `data_note` | 数据准备说明 |
| `owner_id` | 批次负责人 |

`test_cycle_items`：`asset_type` ∈ `functional/api_case/api_suite/ui_case/ui_suite`，`asset_id` 指向资产；`case_id` 保留给手工用例并可为空；`asset_version` 固定加入批次时的用例版本；`last_run_type/last_run_id` 指向最近一次运行；`attempt_no` 记录尝试数。唯一约束 `(cycle_id, asset_type, asset_id)`。

`test_cycle_attempts`：每次执行/重试一行，记录 `execution_type`、`original_run_type/original_run_id`、`attempt_no`、`status`、`summary`、`evidence_json`、起止时间；唯一约束 `(cycle_item_id, attempt_no)`。

### 2.3 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/test-plans/{plan_id}/cycles/` | 支持 `target_build`/`env_kind`/`env_id`/`credential_ref`/`data_note`/`owner_id` |
| PATCH | `/cycles/{id}` | 同上；改环境时重新冻结快照 |
| POST | `/cycles/{id}/items` | `assets: [{asset_type, asset_id}]` 与旧 `case_ids` 同时可用，重复项跳过 |
| POST | `/cycles/{id}/items/{item_id}/attempts` | 记录一次尝试；终态回写计划项结果与用例 `last_result` |
| GET | `/cycles/{id}/items/{item_id}/attempts` | 单项尝试历史（升序） |
| GET | `/cycles/{id}/attempts` | 批次内尝试记录（倒序） |
