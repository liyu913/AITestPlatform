## 3. 数据契约：用例生命周期与执行结果拆分

原 `test_cases.status` 同时承担“用例状态展示”和“最近执行结果”，导致执行失败会把已确认用例改回执行态。
本次拆分（`app/services/functional/testcase_lifecycle.py` 为唯一写入口）：

| 字段 | 含义 | 取值 |
| --- | --- | --- |
| `test_cases.lifecycle_status` | 编写/评审生命周期 | `draft` / `pending_review` / `confirmed` / `archived` |
| `test_cases.last_result` | 最近一次执行结果投影 | `passed` / `failed` / `blocked` / `error`，未执行时为 `NULL` |
| `test_cases.last_result_at` | 结果时间 | 北京时间 |
| `test_cases.version_no` | 当前版本号 | 从 1 开始 |
| `test_cases.archived_at` / `archived_by_id` | 归档信息 | 恢复时清空 |
| `test_cases.status` | **仅兼容**：等于 `lifecycle_status` 的镜像列 | 不再写入执行结果 |

旧数据回填规则：

| 原 `status` | 迁移后生命周期 | 迁移后最近结果 |
| --- | --- | --- |
| `passed` / `failed` / `blocked` / `error` | `confirmed` | 原值 |
| `draft` / `pending_review` / `confirmed` / `archived` | 原值 | `NULL` |
| 其他自由文本（`ready`、`active`、`done`、`new`…） | 接口层映射为 `confirmed` / `draft` | `NULL` |

新增表：

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `test_case_versions` | 用例内容快照，执行/报告引用它 | `(case_id, version_no)` 唯一 |
| `test_case_reviews` | 评审结论绑定到具体版本 | `decision ∈ {approved, rejected}` |
| `requirement_versions` | 需求正文与验收规则快照 | `(requirement_id, version_no)` 唯一 |

`requirements` 新增 `acceptance_rules`（验收规则文本）与 `version_no`。

## 4. 接口契约变更

新增：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/projects/{pid}/workbench` | 工作台：待执行 / 待评审 / 待回归 / 近期执行 |
| GET | `/test-cases/{id}/versions` | 版本列表（含快照） |
| GET | `/test-cases/{id}/versions/{version_no}` | 单版本 |
| POST | `/test-cases/{id}/submit-review` | 送审 → `pending_review` |
| POST | `/test-cases/{id}/review` | 评审 `{decision, comment, version_id}` |
| GET | `/test-cases/{id}/reviews` | 评审记录 |
| POST | `/test-cases/{id}/archive` | 归档，可选 `reason` |
| POST | `/test-cases/{id}/restore` | 恢复为草稿 |
| GET | `/requirements/{id}/versions` | 需求版本列表 |

变更：

| 位置 | 变更 | 兼容策略 |
| --- | --- | --- |
| `TestCaseOut` | 新增 `lifecycle_status` / `last_result` / `last_result_at` / `version_no` / `archived_at`；`status` 仍返回生命周期 | 旧前端只读 `status` 仍可用 |
| `TestCaseCreate/Update` | 新增 `lifecycle_status`；`status` 作为别名 | 创建时执行结果词拆成两轴；更新时执行结果词返回 400 |
| `GET /test-cases/` | 新增 `lifecycle_status` / `last_result` / `include_archived`，默认隐藏已归档 | 旧 `status` 参数按生命周期解释 |
| `DELETE /test-cases/{id}` | 被缺陷/执行项/执行记录引用时返回 409 | 提示改用归档 |
| `finalize_agent_once` | 只写 `last_result`，不改生命周期；结果由断言覆盖率判定 | 返回值签名不变，新增可选 `judgement` |

## 5. 页面原型与导航

```
顶部：LY 测试平台 · 项目切换 · 用户菜单
侧栏：
  概览        工作台 / 项目概览
  测试资产    需求管理 / 功能用例(用例管理·AI 生成用例) / 接口自动化 / UI 自动化 / 知识库
  执行        测试计划与执行(计划列表·功能执行记录)
  质量        缺陷与回归 / 报告与覆盖
  设置        环境管理 / 模块管理 / 成员管理
```

- 进入项目默认落到「工作台」。
- 工作台四象限：我的待执行、待评审、待回归、近期执行；每行都带业务记录链接与状态。
- 旧入口兼容：`/requirements`、`/api-runs/12`、`/test-cases/ai` 等旧链接由 `LegacyRedirect` 跳转到上次访问项目的对应页面；无上次项目时回项目列表。
- 切换项目会卸载当前项目页面（`ProjectShell` 以 `projectId` 作 key），筛选与选择不跨项目残留。
