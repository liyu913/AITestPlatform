### 2.2 升级步骤（生产）

```bash
cd /mnt/d/AITestPlatform/app
./scripts/backup-restore-drill.sh backup            # 1. 备份（自动校验）
git pull                                            # 2. 取到发布版本
./scripts/manage.sh rebuild                         # 3. 重建镜像并等待健康
docker compose exec backend alembic upgrade head    # 4. 迁移
./scripts/smoke.sh                                  # 5. 冒烟
```

顺序要求：**先备份 → 再迁移 → 再切流量**。迁移是“先扩列、后回填、最后切读入口”，旧版本代码在扩列后仍可运行；因此允许迁移与代码发布短暂交错，但回退时必须先回退代码再降级结构。

### 2.3 回退步骤

```bash
./scripts/manage.sh stop
docker compose run --rm backend alembic downgrade 91de45b6c284
git checkout <上一个发布 tag>
./scripts/manage.sh rebuild
./scripts/backup-restore-drill.sh restore <备份目录> --into-scratch   # 先演练
```

注意：`downgrade` 会删除 B2–B6 新增的列与表，并清理仅属于自动化资产的计划项（`case_id` 恢复非空）。数据回退以升级前备份为准。

## 4. 备份与恢复演练

`scripts/backup-restore-drill.sh`：

```bash
./scripts/backup-restore-drill.sh backup                    # 生成 db.sql.gz + uploads.tar.gz + SHA256SUMS
./scripts/backup-restore-drill.sh verify  <dir>             # 校验归档完整性与校验和
./scripts/backup-restore-drill.sh restore <dir> --into-scratch
./scripts/backup-restore-drill.sh restore <dir>             # 生产恢复（要求输入库名确认）
```

`--into-scratch` 会把 dump 导入临时库，逐表比对 `test_cases / test_case_versions / test_cycles /
test_cycle_items / test_cycle_attempts / test_cycle_reports / defects / defect_status_history` 行数，
结束后删除临时库，不触碰生产数据。

**实测结论**：在真实部署栈上完成备份 → 升级 → scratch 恢复比对（8 张表行数一致）→ 接口冒烟。
脚本同时修复了两处实机问题：改用容器内 root（应用账号只授权容器主机名）与从容器环境读取 root 密码。
